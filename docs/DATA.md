# 음식 · 영양제 DB: 공개 원천으로 새로 만들기

작성 2026-11-18. 상태: 계획 (아직 내려받지 않음)

## 1. 원칙

- **공개 원천에서 직접 받아 새로 만든다.** 다른 프로젝트에서 만든 가공 결과물(표, 대응표, 사전)은 가져오지 않는다.
  - 다른 앱이나 서비스에서 뽑아낸 자료는 어떤 형태로도 쓰지 않는다.
  - 코드와 표는 이 저장소에서 새로 쓴다.
- 이용 조건이 「상업 이용 가능 + 출처 표시」 이하인 원천만 쓴다. 조건을 확인하지 못한 원천은 받지 않는다.
- 원본 파일은 저장소 밖(또는 `.gitignore`된 `data-raw/`)에 두고, 저장소에는 **받는 스크립트 · 변환 스크립트 · 작은 결과물 · 매니페스트**만 넣는다.
- 공공데이터포털 · 식품안전나라 인증키는 각자 발급받아 git에서 제외된 로컬 파일에만 둔다(`.gitignore`, `tools/data/fetch.mjs` 참고). 스크립트가 직접 읽고 오류 메시지에서는 가린다.

- 음식 대분류 25개 중 「빵 및 과자류」 8,600 · 「음료 및 차류」 5,776이 대부분 프랜차이즈 줄이다. 분류별 기본 이미지는 이 25개로 만든다.

## 3. 만드는 순서

1. **음식 1단계 (완료, 6절):** 식약처 음식 DB를 받아 `packages/core/data/foods.json`으로 변환한다.
   - 지금 식단코치 `FOODS` 76개의 영양소 9종(열량 · 탄수화물 · 단백질 · 지방 · 당류 · 나트륨 · 포화지방 + 1회 제공량 g)부터 맞춘다. 영양소는 나중에 늘린다.
   - 1회 제공량 값과 100g당 값을 함께 둔다. 값이 없으면 `null`(0과 구분).
   - 식약처 **식품 대분류**를 `category`로 그대로 쓴다 → 분류별 기본 이미지(4절)를 붙인다.
   - 외식 프랜차이즈 줄은 브랜드 이름이 들어 있으므로 첫 판에서는 뺄지 정한다(질문 1).
2. **음식 검증 (완료, 6절):** 기존 76개가 새 DB에서 같은 이름으로 찾아지는지, 열량 차이가 큰 것은 무엇인지 표로 낸다. `diet.core.js` 테스트가 그대로 통과해야 한다.
3. **영양제 1단계:** C003 + I0310로 국내 생산 중 제품 목록, I-0050 · I-0040 · I2710으로 성분 기준표를 만든다. 브랜드 사전과 번역은 새로 만든다.
4. **영양제 2단계:** DSLD는 받을 범위(브랜드 목록)를 정한 뒤 받는다.
5. 각 결과물마다 `data/manifest.json`에 원천 · 받은 날 · 이용 조건 · 원본 해시 · 줄 수를 적는다. 앱 화면 하단에 출처를 표시한다.

## 4. 기본 이미지

- 음식 사진은 음식마다 만들지 않는다. 사용자가 찍은 사진이 있으면 그것을, 없으면 **식약처 식품 대분류별 기본 이미지**를 쓴다(대분류 약 20~25개).
- 추천 카드에 쓰는 메뉴만 따로 사진을 만든다(지금 시안의 4장).
- 대분류 목록이 확정되면(3절 1단계 뒤) `docs/mockups/img/PROMPTS-categories.md`를 만들어 Codex 앱으로 생성한다. 촬영 톤은 `PROMPTS.md`의 썸네일 조건과 같다.

## 5. 결정 (2026-11-18, 사용자)

1. **외식 프랜차이즈 영양정보를 넣는다.** 업체 · 브랜드 이름을 함께 저장하고 화면에 보인다(`brand` 칸). 값은 업체 제공 영양정보라는 표시를 남긴다.
2. **농진청 국가표준식품성분표(원재료)를 쓴다.** 이 프로젝트는 지금 연구 · 학습 목적이다. 이용 조건은 받을 때 확인해 매니페스트에 적고, 배포나 상업 이용으로 바뀌면 다시 검토한다.
3. **영양제는 전부 넣는다.** 국내 C003 전체(원료용 신고 제외), K-FIND 건강기능식품, 해외 NIH DSLD 전체. 생산 중단 제품은 지우지 않고 표시만 한다.
